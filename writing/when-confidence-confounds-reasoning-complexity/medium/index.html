When Confidence Proxies Confound Reasoning Complexity

What negative controls revealed about entropy, MC-dropout, and uncertainty-weighted RLVR

By Sham Satish Thakare · Working Paper / Research Note · 2026

The Question

When a language model produces a longer reasoning trace, should higher predictive entropy automatically be interpreted as greater uncertainty?

My experiments suggest that this interpretation needs more care.

In reinforcement learning from verifiable rewards (RLVR), methods such as Group Relative Policy Optimization (GRPO) learn from groups of sampled reasoning trajectories. A tempting extension is to use an uncertainty or confidence signal to modify how strongly individual trajectories influence learning.

But that creates a prerequisite question:

Does the uncertainty estimator actually measure what we think it measures?

I investigated this question using mathematical reasoning experiments with Qwen2.5-0.5B-Instruct, diagnostic evaluation on GSM8K, architectural probing, a correct-but-complex stress test, and a controlled RL benchmark.

The central result was not that uncertainty estimation is useless. It was more specific:

An uncertainty proxy can look informative offline while being confounded by properties of the generated trajectory—and even a useful offline error predictor does not necessarily become a useful online credit-assignment signal.

Does Token Entropy Track Sequence Length?

Suppose two reasoning trajectories answer the same kind of mathematical problem.

One is short and wrong.

The other is long, contains several intermediate calculations, and reaches the correct answer.

If the longer trajectory has higher token predictive entropy, should we conclude that the model was less reliable?

Not necessarily.

Longer generations involve more token transitions and more opportunities for variation in the predictive distribution. This creates a potential nuisance variable: sequence length.

If an uncertainty signal is subsequently used to scale policy-gradient advantages, a length-confounded estimator could assign different weights to trajectories for reasons that are not aligned with correctness.

Whether that produces a persistent preference for shorter reasoning during training is a separate empirical question.

I evaluated candidate confidence signals on untouched GSM8K mathematical reasoning problems using Qwen2.5-0.5B-Instruct.

The confirmatory analysis used N = 100 prompt clusters. Token predictive entropy was positively correlated with completion length:

r = 0.486, 95% CI [+0.318, +0.627]

It was also correlated with equation count (r = 0.421). This matters because an apparent relationship between entropy and correctness may partly reflect the complexity or length of the generated solution.

Controlling for completion length: Before controlling for length, the observed association between token entropy and correctness was r = −0.214. After controlling for completion length using partial correlation, it decreased to:

r_partial = −0.092, p = 0.365

In this evaluated sample, the association between token entropy and correctness was no longer statistically significant after controlling for completion length. This suggests that sequence length is an important confound when interpreting token entropy as an error signal.

A Correct-but-Complex Stress Test

Correlation analysis alone does not show what happens on the kinds of examples that matter most for reasoning.

So I also examined a Correct-but-Complex Stress Test.

The comparison asks whether an estimator ranks a long, correct multi-step derivation as more uncertain than a shorter incorrect derivation.

Across the evaluated prompt clusters, token predictive entropy produced this misranking in:

42.1% of paired comparisons

In this stress test, the estimator misranked 42.1% of paired traces. If used directly as a multiplicative policy-gradient weight, such a signal can assign lower weights to some correct longer trajectories for reasons not aligned with correctness.

The MC-Dropout Assumption Needed an Architecture Check

I next examined Monte Carlo dropout.

MC-dropout estimates predictive variation by performing repeated stochastic forward passes with dropout active at inference time.

But before running a large number of such passes, there is a simpler question:

Does the evaluated model actually contain active dropout modules capable of producing that stochasticity?

For the inspected Qwen2.5-0.5B-Instruct configuration, the architecture audit found:

0 active nn.Dropout modules

in the inspected attention and MLP blocks, with attention_dropout = 0.0.

Nominal MC-dropout passes therefore produced deterministic repeated outputs in this evaluated setup:

Var(log P) = 0.0000000000, ΔLogit = 0.0

The resulting policy-update vectors were collinear with standard GRPO in the evaluated calculation:

cos(Δθ) = 1.000000

The conclusion is deliberately architecture-specific. I am not claiming that MC-dropout is invalid for language models generally. Rather, before treating repeated stochastic inference as an uncertainty estimator, inspect whether the model configuration actually contains the stochastic mechanism the estimator requires.

A Better Offline Signal Still Did Not Guarantee Better Online Learning

Self-consistency provided an interesting contrast.

Using K = 4 sampled completions, the observed diagnostic metrics included:

AUROC = 0.812, r_partial = −0.569 (p = 8.1 × 10⁻¹⁰)

This made self-consistency a more informative offline diagnostic signal in the evaluated benchmark.

But that raised the next question:

Does a better offline error predictor automatically become a better online policy-gradient weight?

To test that, I evaluated Consistency-Aware GRPO (CA-GRPO) against matched controls across three independent training seeds (42, 1337, 2026):

Method Group Size (K) Mean Pass@1 (%) [N = 3 Seeds]
Standard GRPO 4 80.00% ± 0.00%
Compute-Matched GRPO 8 78.33% ± 2.89%
Random-Weight Control 4 75.00% ± 5.00%
Permuted-Consistency Control 4 80.00% ± 0.00%
CA-GRPO (Proposed) 4 80.00% ± 0.00%

Across these three evaluated seeds, CA-GRPO and standard outcome-supervised GRPO produced the same observed mean Group Pass@1: 80.00% ± 0.00%.

The observed effect size was Cohen’s d = 0.00.

The permuted-consistency control also produced an observed mean of 80.00% ± 0.00%.

Therefore, in this particular experimental setup, trajectory-specific consistency-aware advantage scaling provided no observed performance advantage over standard outcome-supervised GRPO.

That is not a universal non-inferiority result. With only three training seeds, it should not be interpreted as one.

What Negative Controls Changed About My Interpretation

This experiment reinforced a distinction that is easy to miss:

Offline prediction and online intervention are different problems.

An estimator can discriminate errors reasonably well without providing useful information when inserted into an optimization rule.

Negative controls help separate those possibilities.

  • A permuted signal asks whether the proposed trajectory-specific correspondence actually matters.
  • A random-weight control asks whether generic perturbation produces a similar effect.
  • A compute-matched baseline helps distinguish an algorithmic effect from additional sampling or compute.

Without those controls, an improvement can be too easily attributed to the mechanism we hoped would explain it.

In this experiment, the controls made the result more informative precisely because the proposed method did not outperform the baseline.

What I Learned

  1. Validate an estimator before optimizing with it.
    An uncertainty score should be tested against nuisance variables such as sequence length before it becomes part of a learning objective.
  2. Audit the model architecture.
    An estimator can silently degenerate if its assumed stochastic mechanism is absent from the actual model configuration.
  3. Separate offline discrimination from online utility.
    A metric with useful AUROC does not automatically provide useful policy-gradient credit assignment.
  4. Use negative controls early.
    Permuted, random, and compute-matched controls can reveal whether an apparent improvement actually depends on the proposed mechanism.

What This Study Does Not Establish

The experiments evaluate Qwen2.5-0.5B-Instruct. They do not establish whether the same behavior holds at larger model scales or across other model families.

The diagnostic experiments focus on mathematical reasoning benchmarks, including GSM8K and SVAMP, under the evaluated generation configuration. They do not establish the same behavior for code generation, medical QA, or other open-ended domains.

The controlled RL experiment uses only N = 3 independent training seeds. The observed equality between CA-GRPO and standard GRPO is therefore not a formal demonstration of universal non-inferiority.

The negative controls evaluate trajectory-level advantage weighting. They do not reject step-level Process Reward Models or every possible formulation of uncertainty-aware reinforcement learning.

The result is not “uncertainty weighting does not work.”

The result is that uncertainty estimators should be validated for confounding, architectural compatibility, and online intervention utility before they are trusted as credit-assignment signals.

Where I Want to Take This Next

The next question is whether these observations persist across:

  • larger model scales;
  • different model families;
  • broader reasoning domains;
  • more training seeds;
  • alternative uncertainty estimators;
  • and step-level rather than trajectory-level credit assignment.

A particularly interesting direction is determining which uncertainty signals remain informative after conditioning on reasoning complexity and whether those signals predict actual learning dynamics rather than only offline correctness.

That distinction—between measuring uncertainty and using uncertainty to change learning—is where I think the deeper research problem lies.
